# 报价不提前改写车辆运营计划

## 问题与范围
`world.js` 在调用基础 `commitDraft(skip)` 前就把线路车辆的 `pendingService` 设成全程运营。但 `commitDraft(false)` 可能只打开收费确认，尚未提交；此时取消仍留下新运营计划。当前网页内联建设按钮通常走 `true`，这次修复保留旧报价确认入口的无副作用契约，不调整交互或经济参数。

## 决策
捕获原线路 id，调用基础提交后，仅在 `draft` 已清空（提交成功）时重置待生效运营计划，再保存。实际行程的 `service` 保持不变，仍按既有到站机制切换。无效线路、资金不足、报价与取消都保留原计划。

安卓的打包器先复制网页，再用 `mobile/web-base127/game.js` 与 `world.js` 替换，因此同步修复两份 `world.js`，不改生成目录。

不选择在取消时回滚：期间原本就可能有待生效计划，回滚难以区分来源。不把此逻辑塞进基础 game.js：运营计划的规则继续由 world 层拥有。本次不重排各版本包装链。

## 验证
`node tests/route-commit.cjs` 对网页与安卓基线检查：首次报价无新计划；已有计划在报价/取消、无效编辑、资金不足时保留；成功提交重置计划，当前行程不变；重复提交不重复扣费；存档保存最终计划。旧网页代码失败于“quote queued a schedule”，修复后两份基线均通过。完整网页 32 脚本集成探针同时检查报价取消/扣费/撤回、乘客结算后反复读档及存储配额失败时阻止切图。
