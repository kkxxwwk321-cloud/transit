## 设计方向

玩家在做的事：看网络、找出压力在哪里、拉线、配车、建设施。所以：

1. **地图是主角，界面安静**：三个中心按钮同等分量，只有打开的那个高亮；线路加纸色描边，并行线路之间留出细缝；底部线路区不再占三分之一屏。
2. **每类消息只用一种方式**：引导（首局教学，查看城市时让开，关闭后不再换一种说法出现）；瞬时反馈（付款、建成等反馈显示期间，空闲信息排队，警告和扣命从不延后）；状态（结束局由顶部按钮表达，不再提示「点 ▶ 继续」）；撤回（保持原样）。
3. **决策需要的数字先读到**：「181 人候车 · 容量 24 · 超出 157」放在城市首屏，「满员计时 x/180 秒 · 计满扣一条命」说明另一个数的含义；候车按地区分组，人数列右对齐，便于比较；拥挤城市在地图上直接显示 181/24。
4. **同一套页面尺度**：股票、车辆、设施文字和其他中心页面统一字号与卡片；空状态（地震）不再比实际内容更醒目。

## 复验修复（e9464b6 的两个 P2）

- **改色后「取消」仍保留新颜色**：上游 `setLineColor` 会立即写入线路。现在打开线路设置时记下原颜色：选色仍在地图上即时预览，只有「保存设置」（`applyName`）保留；「取消」、×、Escape 等其他关闭方式都经过 `closeModal`，会恢复原颜色。名称和颜色的「取消」含义一致。单元测试新增此项；用 e9464b6 的代码运行，该测试失败（颜色留在 `#8a9a2e`）。

## 复验修复（2ec01e0：未保存的颜色进入存档）

- **原因**：上一轮的做法是先把选中的颜色写入 `S.lines` 预览，关闭时再改回来。但上游在关闭时先 `save()`，页面离开、中断时也会直接保存 `S`，所以预览颜色可能被写进存档；刷新后，名称恢复成旧值，颜色却保留了新值。
- **修复**：预览不再改动游戏状态。线路设置打开时，选中的颜色只存在设置页的待定状态 `uxLineEdit.preview` 里，地图通过 `lineStyle` 画出预览色；`setLineColor` 在设置页打开期间只记录这个待定值。只有「保存设置」（`applyName`）会把颜色和名称一起写入线路，然后由上游在关闭时保存。取消、×、Escape、刷新、中断都不会让预览进入 `S`，因此也不会进入任何存档。
- **测试**：单元测试改为检查实际存储内容和重新载入后的结果，覆盖四种情况：设置打开时保存（模拟页面离开）后重新载入、关闭时的保存、保存后重新载入，以及选色不改动线路本身。用 2ec01e0 的代码运行，这项测试和复验方的 `probe-color-save.cjs` 都失败；修复后两者都通过。浏览器端用 `verify/reloadcolor.mjs` 真实刷新页面（390×844、1440×900）：刷新后名称和颜色都是旧值。改名断言改为检查预览是否画在地图上，同时确认线路本身没有改动，5 种尺寸通过。22 套 Node 测试全部通过。`ux.js` 版本参数改为 `ux=1108c`。

## 复验修复（078e99c：地图边界限制把城市推到托盘后面）

- **原因**：`uxClampToMap` 按整块屏幕限制地图边界，不考虑托盘、底栏和面板，于是在 461×709、8 线托盘展开时，把河岸镇推到了托盘下面。
- **修复**：可见优先于去掉空带。限制前位于空白地图区（标题栏以下、托盘/底栏/面板以外）的城市，限制后必须仍在该区域内：每个方向的限制位移不得超过这些城市允许的范围；已经靠近边缘的城市可以保持原位，但不会被推得更靠外。必要时会留下一小条地图外空带，而不是让城市被遮住。
- **一并改进**：

## 后期线路「一团乱麻」（2026-11-09）

**诊断**（固定种子的后期场景：13 城、8 线、5 线枢纽）：
1. 车道锥化：并行车道的偏移在每段两端 16% 的长度内收向城市中心，长段上形成长扇形，在枢纽处多个扇形叠成结。
2. 任意角度直线：线路在散布的城市之间按任意角度斜穿，网络中部各种角度互相交叉。
3. 选线面板过高（v1.3.2 之后五条线全部展开），矮屏上看不到它所属的车站。

**设计**：参照交通线路图的画法，只改绘制，路线、距离、票价、计时和经济都不变。
- **地铁图式线路**：车站之间的地面线段画成一段 45° 加一段水平或垂直（`uxOctPath`）。弯折方向按车站 id 固定，所以两个方向、同段所有线路共用一条路径，车道保持并行，弯处法向平滑过渡。`lanePoint` 是线路、车道、车辆、桥梁标记和隧道图案的唯一几何来源，在这里重定义后它们全部同步；车辆和线路共用轨迹函数；实际笔画是离散采样，误差见下方独立复验。
- **必须保持直线的情况**：航线、连接桥头的线段、直线弦或任一折段需要桥或隧道的线段。河流和山体的费用都沿直线计算，折线不能穿过游戏没有计价的水面或山体。
- **线下的道路与轨道**：`drawInfrastructure` 绘制期间拦截城市中心之间的直线笔画，改走同一折线，避免出现「幽灵斜线」。施工与受损标记随之移动。
- **车道收拢**：改为在车站半径加 10 的固定距离内完成（`LANE_RAMP`），线束一直并行到车站，在车站下方汇合。
- **车站留白**：每个车站周围画一圈底色留白，汇入线路越多留白越大，线路在边缘停住，不在中心打结。
- **端点**：编号与延长按钮沿线路最后一段的方向放置。
- **选线面板**：竖屏最高占屏幕一半，列表在面板内滚动，所属车站保持在面板上方可见。

**未采纳 / 限制**：
- 不做线路重排或捆绑路由：交叉是玩家网络本身的几何，改路线会改玩法。
- 同一枢纽的两段线路折成同一 45° 方向时可能短距离重叠，固定场景中由车道并行承接，未见遮挡；其他极端网络未覆盖。
- 安卓打包用 `web-base127/game.js`，没有 `LANE_RAMP` 挂钩，车道收拢在安卓上维持原样；地铁图式线路由 `ux.js` 实现，两端都生效。

## 交通方式分层（2026-11-09）

**判断**：交叉不是问题，问题是层次。公交是局部接驳（线多、站距短），动车/高铁是骨干（线少、运量大），航空不走地面。原来几种方式笔画相近，又按建成顺序互相压盖，眼睛无法分层；动车用深灰枕木点画法，盖住了线路本身的颜色。

**设计**：
- **公交**：最细的实线（上游宽度的 3.4/3.7）。

- **航空**：细虚线 `[7,7]`，透明度降到 0.6，不画底色描边（不切断地面线路）；选中、悬停或正在编辑时恢复。
- **绘制顺序**：公交 → 动车 → 高铁 → 航空（新增 `LINE_ORDER` 挂钩），骨干线路在局部网络上方保持连续。
- **托盘线色条**：公交实线、动车和高铁双线（高铁更粗）、航空虚线，与地图一致（上游原把动车写成 3px 虚线）。

## 折线路径缓存与独立复验（2026-11-10）

- **问题**：`uxOctPlanNow` 原来只用交通类型和站点 id 判断是否重算。东、西两张地图都建公交 `[0,1]` 时，切图后的签名相同，缓存继续引用旧城市对象。完整网页和浏览器均复现：新城市在 `(650,450)` / `(815,370)`，线路仍画在 `(100,750)` / `(265,670)`，端点偏移约 626.50 世界单位，画面中线路消失。
- **决定**：缓存绑定游戏状态对象 `S`。切图、重新开局或读档替换 `S` 时，在 200ms 节流判断之前丢弃旧路径、签名和时间；同一局内仍保留原有网络签名和节流。不改线路形状规划、经济参数和存档。
- **替代方案**：只把地图名称加入签名不能清掉同图重新开局/读档持有的旧城市引用；逐次序列化所有坐标增加每个车道采样点的开销。状态身份直接对应缓存中对象的生命周期。
- **代价与收益**：每次换局或读档重建一次路径；不再跨存档共享路径，同一局的绘制缓存保留。
- **回归**：`tests/release14-dom.cjs` 通过实际建线、保存与切图入口生成同站号的两份存档，检查立即切图和 1000ms 后的线路端点，并检查读档后使用新的城市对象。旧版 `52a8c61` 失败（626.50 单位），修复通过；网页独立探针和浏览器选图流程也通过。资源参数更新为 `ux=1121`。
- **本次独立验收**：26 套 Node 测试通过；390×844、360×740、461×709、844×390、1440×900 的实际浏览器定向检查通过。复验施工/断线标签、线路端点延长报价与取消、付款提示、末尾线路色块、全展开详情、成就页顶部/底部、横屏镜头恢复。浏览器无错误记录。只用鼠标，未重复宣称触摸或真机验收。
